1. Overview

sbJS is a browser‑based tool for creating sprite‑based animations synchronized to music, using JavaScript code.

You:

  • Upload a music track.
  • Upload one or more sprite images.
  • Write a script that animates those sprites over time.
  • Preview the animation in real time.
  • Export:
    • Project files (.dat) you can reopen later.
    • Video data (.dat) containing one image per frame plus audio, to be processed by an external encoder.

This document explains how to use the UI and how to write scripts for animations.

2. Getting Started

2.1 Requirements

  • A modern desktop browser (Chrome, Firefox, Edge, etc.).
  • No server needed: all files are processed locally in your browser.
  • Enough memory/disk space for:
    • Audio file(s).
    • Sprite images.
    • Potentially large rendered video data files (many PNG frames).

2.2 Launching sbJS

  1. Place all files (index.html, style.css, script.js, sandbox.js, classes.js, prism.js, prism.css) in the same folder.
  2. Open index.html in your browser (e.g., drag it into a tab, or double‑click it).

You should see:

  • A top bar with sbJS and buttons: New, Open, Save, Render.
  • A 3‑column layout:
    • Left: Code editor and status console.
    • Middle: Vertical splitter bar.
    • Right: Preview canvas, audio player, sprite list.

3. Interface Overview

3.1 Top Bar

From left to right:

  • sbJS – app name.
  • New – starts a new empty project (asks for confirmation).
  • Open – loads a previously saved .dat project file.
  • Save – saves the current project as a .dat file.
  • Render – renders the current scene into a video data .dat file (image frames + audio).

3.2 Main Layout

The main area is divided into two columns:

  1. Left Column (Code & Status)
    This column is further split horizontally:

    • Code Editor (top)
      • A monospace JavaScript editor with syntax highlighting.
      • Your script is entered here.
    • Horizontal Splitter (drag to resize vertical ratio).
    • Status Panel (bottom)
      • Displays output from print() calls in your script.
      • Shows errors in red when your script fails to run.

  2. Right Column (Preview, Audio, Sprites)
    This column is also split horizontally:

    • Preview Area (top)
      • Canvas Preview – shows the current frame of your animation.
      • Audio Player – native <audio> element for playing/pausing/seeking the music.
    • Horizontal Splitter (between preview and sprites).
    • Sprites Panel (bottom)
      • Left side: two buttons:
        • Music icon – upload/replace music.
        • Image icon – upload new sprite.
      • Right side: list of sprites (thumbnail, name field, delete button).

3.3 Splitters / Resizing

The app uses draggable gutters:

  • Vertical splitter (center): resize code side vs. preview/sprites side.
  • Horizontal splitters:
    • Between code editor and status panel.
    • Between preview area and sprites panel.

You can drag these to adjust the layout. The preview canvas auto‑resizes to maintain a 16:9 aspect ratio within its pane.

4. Working with Music

4.1 Import Music

  1. In the sprites panel (bottom‑right), click the music icon (tooltip: “Upload music”).
  2. Select an audio file (audio/* – e.g., .mp3, .ogg, .wav).
  3. The audio is loaded and shown in the audio player.

The current music is used for:

  • Playback preview (you control via the audio player).
  • Render (length and content of exported video data).

If a track is already loaded, you will be asked to confirm replacement.

4.2 Playback Controls

Use the standard audio controls:

  • Play / Pause
  • Seek bar – change current time.
  • Volume and mute (browser‑dependent UI).

When playing:

  • The preview updates continuously, synchronized to the current audio time.
  • When you seek, the preview updates to reflect the new time.

5. Working with Sprites

5.1 Adding a Sprite

  1. In the sprites panel, click the image icon (tooltip: “Upload new sprite”).
  2. Choose an image file (image/* – e.g., .png, .jpg).
  3. The sprite appears in the list with:
    • Thumbnail preview.
    • Name input field.
    • Delete icon.

sbJS assigns an initial unique name:

  • "New sprite", "New sprite (2)", "New sprite (3)", etc.

5.2 Sprite Names and Scripting

Sprite names are important:

  • In your script you create sprites by passing a string name to the Sprite constructor.
  • That name must exactly match the name of one of the uploaded sprites (case‑sensitive) for it to render.

Example: if your sprite list shows a sprite named logo, in your script:

const logo = new Sprite("logo");

If you typo the name (e.g. "Logo"), the sprite won’t appear in the preview.

5.3 Renaming Sprites

  • Edit the name input in the sprite list.
  • The new name is immediately applied.
  • Update your script to use the new name if needed.

5.4 Deleting Sprites

  • Click the trash icon on the row of the sprite you want to remove.
  • Confirm in the dialog.
  • The sprite is removed from the project.

Any Sprite("thatName") in your script will then refer to a name that no longer exists visually. The code will still run, but nothing will be drawn for that sprite.

6. Writing Scripts

Scripts are written in plain JavaScript in the left editor.
Every time you modify the code:

  • It is sent to a sandboxed worker for evaluation.
  • If it runs successfully, the scene is updated and the preview redraws.
  • If it throws an error, the error message is shown in red in the status panel.

6.1 Script Environment

Your script is executed as:

new Function("Sprite", "print", code);

So:

  • You are provided with:
    • Sprite – the class you use to define animated sprites.
    • print – a function to log messages to the status panel.
  • You can use normal JavaScript features:
    • Variables, functions, loops, etc.
  • You do not interact with the DOM here; this code runs in a Web Worker.

6.2 The Sprite Class

Sprite defines an animated object in your scene.

const mySprite = new Sprite("spriteName");
  • spriteName: String, must match a sprite’s name in the sprite list.

Once created, you define animation events using methods:

6.2.1 Generic move

mySprite.move(type, startTime, targetValue, duration = 0, easing = "linear");
  • type – which property to animate:
    • "x" – horizontal position (0.0 = left, 1.0 = right).
    • "y" – vertical position (0.0 = top, 1.0 = bottom).
    • "size" – scale multiplier (1.0 = original size).
    • "angle" – rotation in radians.
    • "alpha" – opacity (0.0 = invisible, 1.0 = fully opaque).
  • startTime – when the animation starts, in seconds (same as audio time).
  • targetValue – value at the end of this event.
  • duration – how long the event lasts, in seconds:
    • 0 = instant jump at startTime.
    • > 0 = interpolation from current value to targetValue over time.
  • easing – one of:
    • "linear" (default; straight interpolation),
    • "easeIn",
    • "easeOut",
    • "easeInOut".

6.2.2 Convenience Methods

For convenience, you can call:

mySprite.moveX(startTime, targetValue, duration = 0, easing = "linear");
        mySprite.moveY(startTime, targetValue, duration = 0, easing = "linear");
        mySprite.scale(startTime, targetValue, duration = 0, easing = "linear");
        mySprite.rotate(startTime, targetValue, duration = 0, easing = "linear");
        mySprite.alpha(startTime, targetValue, duration = 0, easing = "linear");

These are equivalent to move("x", ...), move("y", ...), etc.

6.2.3 Initial Values

If you don't set any events, default sprite properties are:

  • x: 0.5 (center horizontally)
  • y: 0.5 (center vertically)
  • size: 1 (original image size)
  • angle: 0 (no rotation)
  • alpha: 1 (fully visible)

6.3 Coordinate System and Units

  • Time – seconds; synced with audMusic.currentTime.
  • Positions – normalized:
    • x = 0 → left edge of screen.
    • x = 1 → right edge.
    • y = 0 → top.
    • y = 1 → bottom.
  • Size (size) – multiplies image’s intrinsic dimensions.
  • Angle (angle) – radians (e.g., Math.PI ≈ 180°, Math.PI / 2 ≈ 90°).
  • Alpha (alpha) – opacity from 0 to 1.

6.4 Debugging with print

Use print() to display messages in the status panel (bottom left):

print("Script loaded");
        print("Sprite x start time is " + startTime);
  • Each call prints a line.
  • On success, messages appear in light gray.
  • On error, the error message replaces the status content and appears in red.

6.5 Example Scripts

6.5.1 Basic Example

print("Hello, sbJS!");

        // Make sure a sprite named "logo" exists in the sprite list.
        const logo = new Sprite("logo");

        // Move logo from left to right between 0s and 5s
        logo.moveX(0, 0.0);             // instantly at time 0, x = 0 (left)
        logo.moveX(0, 1.0, 5, "easeInOut"); // from t=0 to t=5, move to x=1 (right)

        // Fade in from 0s to 2s
        logo.alpha(0, 0.0);           // start fully transparent
        logo.alpha(0, 1.0, 2, "easeOut");

        // Slight scale up at 3s (instant)
        logo.scale(3, 1.2);

        // Rotate from 4s to 8s
        logo.rotate(4, 0);               // start at angle 0
        logo.rotate(4, Math.PI * 2, 4);  // spin 360° over 4 seconds

6.5.2 Multiple Sprites

const bg = new Sprite("Background");
        const text = new Sprite("Text");

        // Background: always visible, slowly zooming in
        bg.scale(0, 1.0);
        bg.scale(0, 1.3, 30, "easeInOut");

        // Text: fade in at 5s, drift up
        text.alpha(5, 0);
        text.alpha(5, 1, 1, "easeIn");

        text.moveY(5, 0.7);
        text.moveY(5, 0.3, 10, "easeOut");

        print("Scene setup complete.");

Make sure you have sprites named Background and Text for this example.

7. Previewing the Animation

7.1 Automatic Updates

  • Every time you change the script:
    • The scene is recalculated.
    • The preview is updated (for the current audio time).
  • When music is playing:
    • The preview continuously re‑renders to match the audio position.

7.2 Seeking

  • Drag the audio player’s seek bar.
  • The canvas updates to show the frame at that new time.

7.3 Error Handling

If your script throws an exception:

  • Preview continues to show the last successful scene.
  • Status panel shows the error message in red.
  • Fix your code; on the next successful run, the scene is updated.

8. Project Files: New, Open, Save

8.1 New Project

Button: New

  • Asks: “New project? All unsaved changes will be lost”.

  • If confirmed:

    • Clears music.
    • Clears sprites.
    • Creates a fresh scene.

    • Resets the editor to:

      print("Hello, world!");

Use this when starting from scratch.

8.2 Save Project

Button: Save

  • Packages the current state into a JSON object:

    {
        "music": "<data URL of audio>",
        "sprites": [
            { "name": "SpriteName", "data": "<data URL of image>" },
            ...
        ],
        "code": "/* your script as a string */"
        }

  • Encodes it with Base64.

  • Downloads a file named like:

    sbJS_Project_YYYY-MM-DDTHH:MM:SS.sssZ.dat

Use this for:

  • Backing up your work.
  • Sharing projects with others who also have sbJS.

8.3 Open Project

Button: Open

  • Asks: “Open project? All unsaved changes will be lost”.
  • If confirmed:
    1. Prompts you to choose a .dat file created by sbJS Save.
    2. Reads and decodes its contents.
    3. Restores:
      • music,
      • sprites,
      • code (editor content).
    4. Re‑evaluates the restored script and updates the scene.

If the file is not a valid sbJS project, behavior is undefined (likely an error in the status panel).

9. Rendering Video Data

Button: Render

Rendering exports all frames of your animation as PNGs plus the audio, wrapped in a single .dat file. This is meant to be post‑processed by a separate encoder (not included in this project).

9.1 Process

  1. Button state changes to:
    • Text: Rendering...
    • Disabled (no clicks).

  2. The app computes the number of frames:

    frameCount = Math.floor(audMusic.duration * 60);

    → ~60 FPS for the entire duration of the audio.

  3. For each frame i from 0 to frameCount - 1:

    • Set audMusic.currentTime = i / 60.
    • Render the frame.
    • Convert the internal buffer canvas to a PNG data URL.
    • Append it to video.frames.
    • Update button text: Rendering... i/frameCount.

  4. At the end:

    • Prepare object:

      {
        "frames": ["data:image/png;base64,...", ...],
        "audio": "<data URL of audio>"
        }

    • Base64‑encode it.

    • Download as:

      sbJS_Video_YYYY-MM-DDTHH:MM:SS.sssZ.dat

    • Restore button state to Render and re‑enable it.

9.2 Notes and Caveats

  • Rendering can produce very large files:
    • Duration (seconds) × 60 frames × PNG size.
  • Rendering happens in the browser; expect it to take time for longer tracks.
  • The .dat video file is not directly playable; you must write or use an external tool to:
    • Decode Base64.
    • Parse JSON.
    • Combine the PNG frames and audio into a proper video file (e.g., via ffmpeg).

10. Tips & Limitations

  • Sprite name management
    • Always ensure your script’s Sprite("name") strings match the names in the sprite panel.
  • Event ordering
    • Internally, events are sorted by startTime.
    • Multiple events can target the same property at different times; later ones override earlier ones after their durations.
  • Performance
    • Many high‑resolution sprites and complex scripts may slow down preview and especially rendering.
  • Browser limitations
    • Everything runs client‑side; max project size is constrained by browser memory and performance.
  • No undo
    • There is no undo stack; use Save frequently to keep versions.
